# 手部残影修复 · v6.3.1

2026-11-06，用户在评分页候选 B 看到举手时有透明手指和手臂叠影。静止帧可以复现。

## 根因与影响范围

`GestureLibrary.raw` 原先把动作力度乘到全部手臂输入，其中也包含 `Movement1`（持草手臂）、`Movement2`（左侧举手/抚胸）、`Movement3`（右侧指点）。这些输入控制模型替换图层的显隐。力度 0.7 会让替换手臂以 0.7 的透明度显示，同时默认手臂仍以 0.3 显示。较弱动作会长期停留在两套图层都可见的状态。

复现中，`chest` 的举手图层和默认手分别为约 0.7/0.3，`point`、`grass` 也出现同类叠影。`thanks` 和 `explain`/`refuse` 的相应变体共用这些原语，同样受影响。张掌挥手的保持阶段使用默认手图层，未观察到同类持续半透明；截图中的举手/致谢动作容易被认为是挥手，所以按实际图层与执行动作排查全部手势。

修复前原始参数、drawable 透明度及截图保存在 `test-results/hand-ghost/before/`。举手截图为 `chest-0-0.7.png`，指点为 `point-0-0.7.png`。

## 修复

动作力度只缩放连续关节参数，保留原生图层选择与指形过渡。`src/hand-style.ts` 统一将三个替换图层输入归一为 0/1，并使右侧持草/指点图层互斥。Controller 原生动画路径与 Engine 最终组合路径均调用同一规则，覆盖原生动画的短交叉淡化、手动参数、动作层的进入/退出混合及中断切换。

手指物理、腕部运动与躯干动作继续使用原曲线；原始角色资源和 SDK 未修改。眼型已有同类互斥处理，身体动作只改变关节/重心，衣着由独立外观模块拥有，不经过手势力度缩放。

## 验证与数据

`npm test` 包含手型互斥、post 阶段覆盖、所有变体在低力度下保持原生手型并降低关节幅度的检查。`npm run test:hand` 对 7 种手势 × 3 变体 × 3 档力度，检查实际 Cubism drawable 的图层透明度，覆盖进入、保持、退出和回归，以及手动中断替换和 6 条原生进出动画。阴影素材本来就可能半透明，测试检查图层组与默认手是否同时出现，保留正常阴影。

源码更新后，旧评分样本保留其代码/模型来源和播放记录。重新观看修复后的效果需要准备新的候选，避免把新渲染效果覆盖进旧 take。此前人工选择不会被重写。旧数据仍需在正式导出训练集前审核。

本轮结果：79 项单元/接口检查通过，TypeScript 与构建通过；63 组手势及中断/原生动画共 6875 个图层状态采样通过。修复后的样例截图与完整报告在 `test-results/hand-ghost/after/`。

评分页真实 Qwen 音频回归也通过：停止/重播、A/B/C 共用音频、实际执行采样、刷新恢复与人工提交落盘。测试评分写入隔离目录。
