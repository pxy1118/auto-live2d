# 表演对比与偏好采集

运行时 `v6.3.2-feedback-acting`。默认模型包继续使用 `vtuber-v6-native28-motion-r2`，本轮没有训练模型。

## 使用

主页右上角点击“表演评分”，或打开 `http://127.0.0.1:8765/review`。评分页与说话页共用一个角色窗口。选择一条练习台词或自己输入台词和语境，点击“准备候选”。音频只生成一次，随后按 A、B、C 播放；全部看完后选择更喜欢的版本，也可以选“都不合适”或“差不多”。各版本的 1～5 分和问题备注可选，最后明确点击“保存选择”。

“停止”会中止准备或播放，中断的候选必须重新完整观看才能评分。“已保存的样本”可以恢复未完成样本。重播会产生新的播放记录，后续评分引用新记录；旧评分和其引用的旧记录保留。评分不会自动开始训练。

内置 100 条练习：28 种原生情绪每类 3 条，共 84 条；另有 16 条混合情绪、转折、延续、平静说明、否定和转述场景。台词覆盖标签是编写意图，不是分类真值，也不是人工情绪标注。音频按需生成，不会启动 100 条批量推理。

## 候选设计

三个候选共用逐字节相同的 Qwen 音频与语境，开始前清空情绪/动作历史并等待旧姿态退出，恢复样本创建时的外观。播放时继续使用真实情绪分类、动作模型和连续背景头。

- A：当前自动方案。
- B：对已有非 none 动作换一个变体，力度乘 0.7，起点推迟 120 ms（遵守现有上限）。
- C：换另一个变体，适度增加力度；模型选择 none 且当前情绪明确时，允许尝试该情绪的身体配方。平静或含混状态不会凭空加入动作。

这是启发式候选探索，不是三个新模型，也不是已经通过自然度校准的方案。有些台词可能三个候选都选择 none，或候选因忙碌/冷却而没有执行，用户可以选择“差不多”。记录同时保留模型原始计划、候选计划、最终执行动作和调度器拒绝原因，后续训练必须区分它们。评分期间的候选策略不影响日常自动说话。

自动表情目前仍来自同一套 28 维形变曲线；候选主要比较身体/手势变体、力度及起点。对表情本身的不满可通过“表情不自然”备注收集，随后调整曲线；不要把当前偏好数据声称为面部动画生成监督。

## 本地文件与可追溯性

默认保存到 `datasets/emotion-acting-review-v1/<case_id>/`，该目录在 git 忽略列表内：

- `case.json`：台词、语境、场景 ID、外观、音频校验值、候选完成情况、最近一次评分。
- `audio.ndjson`：Qwen 原始音频流，包括 PCM 与口型/音频特征；重播只换播放 ID，不重新合成音频。
- `take-<id>.json`：每次实际播放的完整记录。约每 100 ms 发起一次状态采样，保存实际采样时间、音频时间、表演时钟、28 维情绪曲线、64 维输入、纯动作历史、面部/身体/手部参数、计划与动作执行历史。它不是逐帧动作捕捉数据；采样会受运行负载影响。
- `rating-<id>.json`：明确提交的人工选择、可选分数、问题标签与备注，引用三次已完整播放的 take ID。每次提交生成新文件，旧评分不被覆盖。

每个样本保留运行时版本、代码和契约 SHA-256、模型检查点信息与 TTS 配置。音频和模型版本会在重播前校验；代码配置变化需要生成新样本，避免把不同表现混作同一候选。服务意外停止后，未完成记录保持中断状态。

`choice=neither` 表示这组三个候选都被否定，**不能直接转换成动作 none 的训练标签**。`choice=tie` 也不指定赢家。所有评分初始为 `training_ready=false`，需后续人工/脚本审核、按场景划分训练验证测试集，再导出训练数据。相同场景的改写与重播应归在同一划分内。

## 接口

仍使用 `POST /api/command` 与标准 `{method,params,request_id}` 信封：

- `review.create`：`text`（1～180 字）、`context`（最多 800 字）、可选 `scenario_id`；生成共用音频。
- `review.list`：列出样本和当前忙碌状态。
- `review.get`：`case_id`，读取样本状态。
- `review.play`：`case_id`、`candidate`（A/B/C）。
- `review.stop`：中止正在准备或播放的候选。
- `review.rate`：`case_id`、`choice`（A/B/C/neither/tie）、`takes`（三个当前已完整观看的 ID）、`scores`（A/B/C 各为 null 或 1～5）、`issues`、`note`。

同一个 request_id 重试相同请求可去重。只允许本机使用；不会发送评分到外部服务。测试通过 `LIVE2D_REVIEW_ROOT` 将模拟评分写入隔离的测试目录，不混入用户数据。

## 验证

`npm test` 包含候选参数范围、原生标签覆盖、候选变体不被再次覆盖、未观看/中断/过期 take 不可评分，以及评分修订不覆盖旧文件的检查。`npm run test:review` 使用真实模型与 Qwen 音频完成生成、停止、三个候选重播、刷新恢复及保存选择；报告与桌面/手机截图在 `test-results/preference-review/`。

首轮人工评分审阅与校准见 [反馈处理记录](review-feedback.md)。旧 take 与评分保留，源指纹更新后重新准备候选即可查看新版；不要求把旧样本重新标一遍。
