# 本地语义表演接入记录 · 2026-11-04

已完成文本、语境和导演要求到真实 Live2D 表情、协调动作及原音色的完整链路。入口为 `python main.py --semantic`；当前模型为已有 Qwen3.5-4B 的完整生成式调用，没有训练新权重。普通启动的 v4 模型指针保持原值。

## 交付行为

- 以完整句子理解台词，区分角色台词、观众发言、事实语境与导演指令。
- 显示简短语义释义，输出连续 VAD、表达语气和带原文片段的动作意图。
- 本地 JSON 约束限定结构与动作枚举；原文片段只允许来自实际输入。严格校验仍在生成后执行，必要时最多重试一次并保留原始输出。
- 原音色与语义规划并行准备，收齐本句语音后按实际音频时钟播放。句内表演暂用字符位置占比定位，不是逐词对齐。
- 表情、视线、身体和手势分层执行；口型、眨眼、物理、特殊眼型的互斥规则和显式外观控制继续运行。长停顿后脸部状态回落。
- 规划或播放期间可停止，迟到输入不能重启旧会话；停止后可直接开始下一次表演。未来分句的显式导演在第一帧也优先于自动动作。
- 新入口隐藏依赖旧专家的实验面板，将手动动作、表情和外观工具收进展开区。旧客户端会收到刷新提示，避免只播放声音却未加载语义执行层。

## 最终功能验证

证据：`test-results/semantic-live2d-r1/final/browser-report.json` 与 `summary.json`。验证在独立的本地 8777 页面执行，使用实际 GPU 模型、实际 TTS 和真实 Cubism 渲染；该辅助服务及测试浏览器已关闭。主入口 8765 保持新方案运行。

| 场景 | 最终语义/表达 | 实际检查 |
| --- | --- | --- |
| 欢迎观众，明确要求挥手一次 | 问候、warm | 一次挥手进入动作层，手腕有位移，口型开合；暂停和继续保持媒体时钟 |
| 我没有生气，只是想把事情说清楚 | 否认生气、calm | 没有误启动挥手或愤怒黑脸 |

最终五个场景的首段音频等待为 **3.669～6.322 秒**。这是本机的小样例功能测量，包含本地语义准备和本句语音缓冲；不是大样本延迟基准。不能沿用旧 v4 的首音成绩。

最终检查：62 项 TypeScript 测试、17 项 Python 测试、中文约束解码探针与生产构建通过。启动器停止记录见 `test-results/semantic-live2d-r1/launcher-stop-verified.json`，确认旧一轮服务完整退出。旧测试、评分、模型指针和发布快照未改写。

## 保留的边界

这些场景参与了开发与提示迭代，结果只说明对应功能跑通，不能作为独立语义准确率或自然度盲测。模型依然可能误解复杂指代、反讽和含蓄语境；合法 JSON 不代表理解正确。真实效果需要在未参与开发的台词与语境上继续检查。

当前总输入预算为 4096 token，包含提示、语境和已知台词；超出时会明确报错。长文本建议分批发送。声音使用原有音色与 RMS 开合嘴，没有新增音素级口型或情绪化 TTS 训练。

桌面检查工具因无法确认当前浏览器地址而停止，未继续操作那个窗口。功能验证改在已知本地地址的专用测试页面完成；用户现有角色页需要手动刷新一次加载新客户端。
