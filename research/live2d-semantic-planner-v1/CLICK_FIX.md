# 当前页点击无反应修复 · 2026-11-04

用户实际使用的内嵌浏览器页面显示“已有其他模型窗口”，另一个旧页面仍持有 WebSocket 控制权。原“开始语义表演”通过 HTTP 远程解锁声音，实际上触发了旧窗口的 AudioContext，既没有解锁当前页，也没有让当前页拥有控制权。

修复后，按钮在当前文档的可信点击事件中直接启用 AudioContext，并显式申请窗口接管。服务端取消旧会话、退役旧请求、切换到新窗口，再关闭旧连接；旧连接的迟到结果和状态不能污染新窗口。原页面及其输入不被删除。

新增“在此窗口控制”和“启用声音”入口。准备、播放、停止与完成状态分别显示，避免台词播完后仍提示“正在准备”。用户原来的台词、语境和导演输入已保留。

验证：

- 在用户当前的内嵌浏览器页面直接点击按钮，完成控制接管；没有使用允许自动播放的测试开关。
- 用户原来的四个分句完整播放，当前页显示“本地已连接”和“本次表演已完成”。API 记录为 `driver=semantic`、`audio_enabled=true`、`clause=3`、`media_ms=8960`，无会话错误。
- 新增服务端接管回归，检查第二窗口默认等待、显式接管、旧待执行请求失败，以及旧连接关闭不影响新拥有者。
- `npm test` 现在默认覆盖语义层与接管回归，共 63 项通过；生产构建通过。

证据保存在 `test-results/semantic-click-fix/actual-iab-playback.json` 和 `current-page.png`。前者在播放完成后采样，不用其中的嘴部零值推断播放期间没有口型。

此前独立验证页面与允许自动播放的浏览器配置没有覆盖这个用户路径。本次修复已将浏览器验证脚本改为默认自动播放策略，通过真实“启用声音”点击启动。
