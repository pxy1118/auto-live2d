# 整段连续语音与响应速度修复

日期：2026-11-04。范围：用户报告“响应太慢、一段话分句说”的实际播放链路。纯本地运行，没有调用在线模型。

## 结果

同机默认四句台词、相同音色与种子，旧版从提交到结束 24.961 秒，最终版本 11.867 秒。旧版调用语义与 TTS 各四次；新版各一次，只有一个 speech_id，播放器 underruns 为 0。最终版本首音 3.117 秒；真实页面按钮另测首音 3.337 秒，直到界面显示完成共 12.989 秒。

| 场景 | 首音等待 / 秒 | 总耗时 / 秒 |
| --- | ---: | ---: |
| 默认四句整段 | 3.117 | 11.867 |
| 欢迎并挥手 | 2.351 | 7.228 |
| 否认生气、平静解释 | 1.895 | 5.812 |
| 同句、赞许语境 | 1.524 | 3.151 |
| 同句、反讽语境 | 1.645 | 3.106 |
| 停止后恢复说话 | 1.777 | 4.867 |

这是开发场景的单次实机对照，包含真实模型、原 Qwen3-TTS 音色、Cubism 和浏览器音频；不等于延迟分位数、自然度盲测或开放域语义准确率。总耗时包含实际说话与动作收势。TTS 仍会保留自然句间停顿。

## 改动

1. 语义模式的增量输入先缓冲，直到 finish 或显式 flush 才作为整段提交，句号和逗号不再重启规划与合成。页面一次发送完整台词，最大 300 字；原 v4 流式分句逻辑保留。
2. 完整台词只进行一次语义规划和一次连续 TTS。语义等待期间有界缓冲 PCM，通过语义合同校验后立即开始播放，继续接收其余音频，无需等最终 WAV。
3. 音频未生成完时使用预计长度，收到最终样本数后只修正未触发的语义事件。已经触发的手势不重播，已确认的身体和手臂曲线保留自身速度。默认四句实测在 TTS 合成结束前已开始播放。
4. 使用本机既有 llama.cpp CUDA 专用引擎；由原始 Qwen3.5-4B 权重本地转换为 Q8_0。保持完整语义 JSON 合同、角色/观众区分与严格原文锚点校验。没有换成关键词规则或更小模型。
5. 新增引擎监听 127.0.0.1:8767，使用 offline 模式，由 Windows 启动器的 Job Object 管理。语义取消会关闭本次推理流；关闭启动器会清理新增引擎。四个自有端口 8765/8767/8768/8769 的停止检查通过。
